6.15 星期一 对话记录

本文件记录 2026-06-15 今天围绕 SmartWardrobe 固件修改、回零逻辑、编码器闭环移动和 v1.4.6 测试指令的关键内容。

一、ALL HOME 回零逻辑

1. 用户最初确认的问题
- 原程序中，单个电机 HOME 到行程开关后，只会急停对应电机，不会自动清零编码器。
- 原 `ALL HOME RPM=xx` 逻辑是：只要 M1、M3、M4 中任意一个轴已经触发行程开关，整个 ALL HOME 就不会启动。

2. 已修改后的行为
- `ALL HOME RPM=xx` 只作用于 M1、M3、M4。
- 如果 M1/M3/M4 中有一个或两个已经在行程开关，已触发的轴会跳过，未触发的轴继续回行程开关。
- 如果 M1/M3/M4 全部已经在行程开关，直接返回已完成状态，不启动电机。
- 等 M1/M3/M4 全部到位后，自动清零 EC1、EC3、EC4，并将 XYZ 坐标归零。
- M2 的特殊 RS485 绝对值编码器不参与 ALL HOME 清零。

3. 当前三轴映射
- X = M1
- Y = M3
- Z = M4
- M2 不参与 XYZ 坐标。

二、旋转轴确认

1. 用户最终确认
- 旋转轴不是 M3，也不是 M5。
- 旋转电机对应特殊编码器 2，因此旋转轴改成 M2。

2. 当前命令
- `M2 ROT_STATUS`
- `M2 ROT_ZERO`
- `M2 ROT_SET STEP=...`
- `M2 ROT_SAVE`
- `M2 ROT_GET`
- `M2 ROT_LIMIT_SET STEP=...`
- `M2 ROT_LIMIT_GET`

3. 注意
- `M2 ABS_*` 是 M2 的 RS485 绝对值编码器角度命令。
- `M2 ROT_*` 是 M2 旋转轴开环步数基线和限位命令。
- 两者都作用于 M2，但用途不同。

三、XYZ 坐标和编码器计数的区别

1. XYZ 坐标来源
- 程序里的 XYZ 坐标来自电机累计步数，不是编码器计数。
- `X/Y/Z` 是 MotorCtrl 中电机输出脉冲累计得到的软件坐标。

2. 编码器计数来源
- EC1、EC3、EC4 是实际编码器反馈计数。
- 普通编码器使用 STM32 定时器正交编码器模式。
- 360PPR 编码器四倍频后为 1440 count/rev。

3. 现场现象
- 用户发现 M1 编码器计数为负。
- 后来用户通过反接编码器 A/B 线，编码器方向恢复正常。
- 因为硬件方向已经正常，所以不再做 E1 软件取反。

四、编码器闭环移动方案

1. 方案选择
- 保留旧 `AXIS MOVE`，不直接改动旧开环电机步数规划。
- 新增编码器闭环移动，先用于现场验证精度。

2. 已新增/扩展的命令

单轴相对编码器闭环移动：
- `M1 ENC_MOVE DIR=CW RPM=20 CNT=360 TOL=36`
- `M3 ENC_MOVE DIR=CW RPM=20 CNT=360 TOL=36`
- `M4 ENC_MOVE DIR=CW RPM=20 CNT=360 TOL=36`

三轴绝对编码器闭环移动：
- `AXIS ENC_MOVE X=720 Y=720 Z=720 RPM=30 TOL=36`

3. 映射关系
- `AXIS ENC_MOVE` 中 X 使用 EC1。
- `AXIS ENC_MOVE` 中 Y 使用 EC3。
- `AXIS ENC_MOVE` 中 Z 使用 EC4。

五、v1.4.6 精度测试重点指令

这是今天最重要的测试记录。

1. 先确认版本

发送：
VER

期望返回包含：
SmartWardrobe-STM32F407 v1.4.6

2. 回零

发送：
ALL HOME RPM=120

等待返回类似：
OK ALL HOME_ZERO_DONE EC=1,3,4 AXIS=XYZ

3. 测试 10cm 左右的三轴编码器闭环移动

发送：
AXIS ENC_MOVE X=720 Y=720 Z=720 RPM=30 TOL=36

说明：
- 按现场实测，720 count 大约等于 10cm。
- TOL=36 大约等于 5mm。
- 三轴应在 EC1、EC3、EC4 接近 720 count 时停止。
- 因为这是绝对编码器目标计数，如果当前 EC1/EC3/EC4 已经是 0，则大约移动 10cm；如果当前位置不是 0，则实际移动距离等于“目标计数 - 当前计数”对应的距离。

4. 更安全的小距离测试，大约 5cm

发送：
AXIS ENC_MOVE X=360 Y=360 Z=360 RPM=20 TOL=36

说明：
- 360 count 大约等于 5cm。
- 适合第一次低速测试。
- 如果当前 EC1/EC3/EC4 是 0，三轴大约各移动 5cm；如果当前计数已经接近 360，则会少动或直接返回已到位。

5. 单轴分别测试

测试 M1：
M1 ENC_MOVE DIR=CW RPM=20 CNT=360 TOL=36

大约移动：M1 相对当前位置移动 5cm。

测试 M3：
M3 ENC_MOVE DIR=CW RPM=20 CNT=360 TOL=36

大约移动：M3 相对当前位置移动 5cm。

测试 M4：
M4 ENC_MOVE DIR=CW RPM=20 CNT=360 TOL=36

大约移动：M4 相对当前位置移动 5cm。

说明：
- `M1/M3/M4 ENC_MOVE` 的 `CNT` 是相对编码器计数。
- `AXIS ENC_MOVE` 的 `X/Y/Z` 是绝对编码器目标计数。

6. 常用计数和位移换算

按今天现场实测比例：
- 72 count 大约等于 1cm。
- 360 count 大约等于 5cm。
- 720 count 大约等于 10cm。
- 36 count 大约等于 0.5cm，也就是 5mm。

常用指令对应位移：
- `AXIS ENC_MOVE X=360 Y=360 Z=360 RPM=20 TOL=36`：从 EC=0 出发时，三轴大约移动到 5cm 位置。
- `AXIS ENC_MOVE X=720 Y=720 Z=720 RPM=30 TOL=36`：从 EC=0 出发时，三轴大约移动到 10cm 位置。
- `M1 ENC_MOVE DIR=CW RPM=20 CNT=360 TOL=36`：M1 相对当前位置移动约 5cm。
- `M1 ENC_MOVE DIR=CW RPM=20 CNT=720 TOL=36`：M1 相对当前位置移动约 10cm。
- `M3 ENC_MOVE DIR=CW RPM=20 CNT=360 TOL=36`：M3 相对当前位置移动约 5cm。
- `M3 ENC_MOVE DIR=CW RPM=20 CNT=720 TOL=36`：M3 相对当前位置移动约 10cm。
- `M4 ENC_MOVE DIR=CW RPM=20 CNT=360 TOL=36`：M4 相对当前位置移动约 5cm。
- `M4 ENC_MOVE DIR=CW RPM=20 CNT=720 TOL=36`：M4 相对当前位置移动约 10cm。

六、现场数据修正

1. 曾经错误示例
- 之前给出 `AXIS ENC_MOVE X=14400 Y=14400 Z=14400 RPM=60 TOL=720`。
- 现场测试发现该值太大，会超过机械可动范围。

2. 问题原因
- 按现场实测，`AXIS ENC_MOVE X=1440 ... TOL=720` 最终停在 EC=720。
- 这是因为程序到位判断是：当前位置与目标差值小于等于 TOL 就认为到位。
- `TOL=720` 太大，等于 10cm 目标的一半，所以会提前停。

3. 已修正
- `AXIS_ENC_MOVE_DEFAULT_TOL` 从 720 改为 36。
- 文档示例改为 `AXIS ENC_MOVE X=720 Y=720 Z=720 RPM=30 TOL=36`。
- 固件版本更新为 v1.4.6。

七、后续建议

1. 先用低速、小距离测试
- 推荐先测 `AXIS ENC_MOVE X=360 Y=360 Z=360 RPM=20 TOL=36`。
- 确认方向、停止位置、编码器计数都正常后，再测 720。

2. 若某轴方向错误
- 如果出现 `ERR 206 Mx_ENC_WRONG_DIR`，说明该轴编码器计数方向和电机命令方向相反。
- 需要调整编码器 A/B 方向或软件方向。

3. 若某轴卡滞
- 如果出现 `ERR 206 Mx_ENC_STALL`，说明电机运行时对应编码器长时间没有计数变化。
- 需要检查编码器接线、供电、A/B 信号和机械联动。

4. 后续更高精度方案
- 先验证编码器闭环移动。
- 再考虑 S 曲线、加速度限制、周期性回零、反向间隙补偿和比例标定。
